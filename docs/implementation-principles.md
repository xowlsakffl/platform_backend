# 백엔드 구현 원칙

작성 기준: 2026-07-28

## 1. 전제

Medi 백엔드는 Java 21, Spring Boot, MySQL, Redis 기준으로 새로 구현한다.

동일하게 유지할 것은 특정 프레임워크 구조가 아니라 아래 항목이다.

- 도메인 개념
- 상태값
- API 흐름
- 운영 정책
- 권한 구조
- DB 관계와 제약

## 2. 우선 구현 대상

1차 백엔드 범위는 다음 도메인이다.

- 계정: user, staff, hospital
- 병원
- 의료진
- 카테고리/해시태그
- 병원 입점신청
- 병원 이벤트
- 이벤트 상담 DB
- 리얼모델 신청
- 미디어
- 운영 히스토리

후순위 범위:

- 토크
- 후기
- 댓글
- 신고
- 채팅
- 알림 고도화
- 광고 캘린더
- 뷰티샵 도메인

## 3. 금지 사항

- 다른 프레임워크의 Action/Query/Policy 구조를 Java 패키지에 그대로 복제하지 않는다.
- DB 테이블명에 임시 브랜드명을 붙이지 않는다.
- API 경로에 임시 브랜드명을 넣지 않는다.
- 화면 표시용 브랜드명을 코드 곳곳에 하드코딩하지 않는다.

## 4. 문서 사용법

Spring Boot 구현 시에는 반드시 다음을 다시 판단한다.

- 이 기능이 1차 MVP에 필요한가
- 상태 전이가 현재 사업 모델에 맞는가
- 개인정보/의료광고 리스크가 반영되어 있는가
- 프론트 화면과 API 계약이 맞는가

세부 문서와 실제 구현이 다르면 구현 전에 문서를 먼저 교정한다.

## 5. 구현 순서

1. 공통 응답/예외/보안 설정
2. 계정과 인증
3. 병원/의료진/카테고리
4. 병원 이벤트
5. 상담 DB와 리얼모델 신청
6. 미디어 업로드
7. 운영 히스토리
8. OpenAPI 기반 프론트 API client 생성
